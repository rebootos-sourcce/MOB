Cloudflare D1 — why not Postgres, why not SQLite file

D1 is SQLite at the Cloudflare edge — same SQL dialect, same driver API, zero ops. Workers bind to it natively (no connection pool, no TCP, no PGPASSWORD). The Electron app never touches D1 directly; it talks to Workers over HTTPS, which means the database is never exposed to the internet. Compared to PlanetScale or Supabase: no monthly seat cost, no VPC, no connection limits. The full 9-table schema runs at under 10ms per query in the Cloudflare London PoP.

Entity relationship graph

9 tables in 3 layers: recording layer (what was captured), transcript layer (what was said), distribution layer (where it goes). recordings is the root — every other table references it directly or through transcripts.


Recording layer
recordings · clips · metadata_tags. The raw capture and its derived clips. All metadata stored before any AI processing.
Transcript layer
transcripts · words · segments · captions. The intelligence lives here — 1 word row per token, energy scored per segment, caption lines ready for SRT export.
Distribution layer
production_packages · distributions. Assembled metadata bundles (title, description, hashtags, chapters) and one row per platform publish attempt.

D1 schema — 9 tables, 3 layers

Complete SQL for Cloudflare D1. All IDs are text with a type prefix (rec-, clip-, trx-) for readability in logs. Integer PKs only on high-volume per-word tables where text IDs would bloat the index.

Intelligence layer — 6 algorithms

Every algorithm runs on data already in D1. No external model calls except the optional Claude API title/description step. All produce rows in existing tables — the intelligence is the data.


1 Filler word detection O(n) · writes: words.is_filler

Single pass over the words table. Filler list is a frozen set — lookup is O(1). Generates a cut list with 50ms pre/post padding so the edit doesn't clip the following consonant.

// fillerDetect.js
const FILLERS = new Set([
  'um', 'uh', 'uhh', 'umm', 'like',
  'you know', 'basically', 'literally',
  'right', 'so', 'actually', 'i mean'
]);

function detectFillers(words, PAD = 50) {
  const cutList = [];
  for (const w of words) {
    if (FILLERS.has(w.word.toLowerCase())) {
      w.is_filler = 1;
      cutList.push({ start_ms: w.start_ms - PAD, end_ms: w.end_ms + PAD });
    }
  }
  return cutList; // merge overlapping ranges before applying
}
2 Silence gap detection O(n) · writes: segments (type='silence')

Scans word-to-word gaps. Threshold is the user-configured pause slider (300 / 500 / 750ms). Produces silence segment rows with exact boundaries for multi-cut concat in FFmpeg.

function detectSilences(words, thresholdMs = 500) {
  const silences = [];
  for (let i = 1; i < words.length; i++) {
    const gap = words[i].start_ms - words[i - 1].end_ms;
    if (gap > thresholdMs) {
      silences.push({
        type: 'silence',
        start_ms: words[i - 1].end_ms,
        end_ms:   words[i].start_ms,
        text:     '',
        wpm:      0,
        energy:   0
      });
    }
  }
  return silences;
}

3 Energy scoring O(n) · writes: segments.energy

Scores each speech segment 0–1 from three factors: speech rate (fast = engaged), keyword density (domain words boost), and sentence length variance (rhythm variation = interesting). Segments above 0.65 are highlight candidates.

function scoreEnergy(segment, domainKeywords) {
  const wpmNorm   = clamp((segment.wpm - 80) / (200 - 80), 0, 1);
  const words     = segment.text.toLowerCase().split(/\s+/);
  const kwHits    = words.filter(w => domainKeywords.has(w)).length;
  const kwNorm    = clamp(kwHits / 5, 0, 1);
  const variance  = sentenceLenVariance(segment.text);  // 0–1

  return 0.4 * wpmNorm + 0.3 * kwNorm + 0.3 * variance;
}
// segments with energy > 0.65 → candidate highlight clips
// contiguous high-energy window (30s+) → auto clip suggestion
4 Caption line formation O(n) · writes: captions table · exports: .srt + .vtt

Greedy word grouping by sentence boundary (punctuation or 1500ms gap). Splits lines at the nearest word boundary below 42 characters. Enforces 1–7 second card duration. Produces SRT and VTT from the same rows.

function formCaptions(words, { maxChars=42, maxLines=2, minMs=1000, maxMs=7000 }) {
  const cards = [];
  let buf = [], bufStart = 0;

  for (let i = 0; i < words.length; i++) {
    buf.push(words[i]);
    const text    = buf.map(w => w.word).join(' ');
    const dur     = words[i].end_ms - bufStart;
    const boundary = /[.?!]$/.test(words[i].word)
                   || (i+1 < words.length && words[i+1].start_ms - words[i].end_ms > 1500)
                   || dur > maxMs;

    if (boundary || i === words.length - 1) {
      cards.push({
        seq:      cards.length + 1,
        start_ms: Math.max(bufStart, buf[0].start_ms),
        end_ms:   Math.max(buf[0].start_ms + minMs, words[i].end_ms),
        text:     wrapLines(text, maxChars, maxLines)
      });
      buf = []; bufStart = i+1 < words.length ? words[i+1].start_ms : 0;
    }
  }
  return cards;
}

function toSRT(cards) {
  return cards.map((c,i) =>
    `${i+1}\n${msToSRT(c.start_ms)} --> ${msToSRT(c.end_ms)}\n${c.text}\n`
  ).join('\n');
}
5 Hashtag extraction — TF scoring O(n) · writes: metadata_tags per platform

Tokenizes full transcript, removes ~200 English stopwords, computes term frequency normalized by doc length. Applies platform-specific depth rules: YouTube gets 10 mixed-reach tags, TikTok gets 20 with broader coverage, LinkedIn gets 8 professional-vocabulary boosted.

function extractHashtags(fullText, platform) {
  const tokens  = fullText.toLowerCase().match(/\b[a-z]{3,}\b/g) ?? [];
  const tf      = new Map();
  tokens.forEach(t => { if (!STOPWORDS.has(t)) tf.set(t, (tf.get(t)||0)+1); });

  const ranked = [...tf.entries()]
    .sort((a,b) => b[1] - a[1])
    .map(([word, count]) => ({ word, score: count / tokens.length }));

  const limits = { youtube:10, tiktok:20, linkedin:8 };
  return ranked
    .slice(0, limits[platform] ?? 15)
    .map(({ word, score }) => ({
      tag:      '#' + word,
      type:     'hashtag',
      platform,
      score
    }));
}

6 Production package assembly D1 reads · writes: production_packages

Pulls captions, hashtags, and segment bookmarks from D1 to build a complete distribution-ready bundle. Title generation is local (keyword extraction from first 500 words) or Claude API (3 variants: curiosity hook, keyword-first SEO, conversational). Chapters are assembled from voice-command bookmark markers.

// Worker: POST /packages
async function buildPackage(recordingId, db) {
  const trx      = await db.first('SELECT * FROM transcripts WHERE recording_id=?', recordingId);
  const captions = await db.all('SELECT * FROM captions WHERE transcript_id=? ORDER BY seq', trx.id);
  const tags     = await db.all('SELECT tag,platform FROM metadata_tags WHERE recording_id=?', recordingId);
  const bookmarks= await db.all('SELECT start_ms,label FROM segments WHERE transcript_id=? AND type="bookmark"', trx.id);

  const hashtagsByPlatform = groupBy(tags, 'platform');
  const chapters = bookmarks.map(b => ({ ms: b.start_ms, title: b.label }));

  const pkg = {
    id:            'pkg-' + Date.now().toString(36),
    recording_id:  recordingId,
    title:         extractTitle(trx.full_text),   // local keyword heuristic
    title_variants: JSON.stringify([]),            // populated by Claude API call if requested
    description:   buildDescription(captions, chapters),
    short_desc:    trx.full_text.slice(0, 280),
    hashtags_json: JSON.stringify(hashtagsByPlatform),
    chapters_json: JSON.stringify(chapters),
    generated_by:  'whisper',
    created_at:    new Date().toISOString()
  };
  await db.run('INSERT INTO production_packages VALUES (?,?,?,?,?,?,?,?,?,?)', ...Object.values(pkg));
  return pkg;
}

08 Distribute to platforms → distributions

One distributions row per platform per attempt. Worker enqueues the upload job, polls platform API for status, updates the row. R2 upload is first (pre-signed URL in clipboard). YouTube is a resumable upload in 8MB chunks. Voice: "Hey MOB upload to YouTube".
