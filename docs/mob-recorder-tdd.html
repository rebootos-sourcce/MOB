MOB Recorder is a performant recording kernel. Build 8 optimized the compositor, encoding pipeline, and idle cost to production-grade numbers. What it lacks is everything after the record button: editing, grading, sharing, and the library that ties it together.

This document maps the gap, specifies each module needed to close it, and assigns implementation priority. The vision is a Record → Edit → Color Grade → Post pipeline in a single Windows executable, with AI-assisted editing and direct social publishing.

The architecture stays the same: one Electron app, one file, no cloud dependency except at the publish step.

06 — Technical Spec · Audio

Audio chain fix — P0 defects

Three confirmed defects in the current audio path, all in src/renderer/recorder/recorder.js.

Fix 1 — Disable browser audio processing

The getUserMedia call currently uses browser defaults. All three processing stages must be explicitly disabled for recording.

// recorder.js — getUserMedia constraints
const audioConstraints = {
  echoCancellation: false,    // was: true (default)
  noiseSuppression: false,    // was: true (default)
  autoGainControl:  false,    // was: true (default)
  sampleRate:       48000,
  channelCount:     2,
};
navigator.mediaDevices.getUserMedia({ audio: audioConstraints, video: false })

Fix 2 — Meter on recording stream, not preview

Current meter reads a separate getUserMedia call. It must analyse the same track that feeds the MediaRecorder.

// After arm() opens the mic track:
const analyser = audioCtx.createAnalyser();
audioCtx.createMediaStreamSource(micStream).connect(analyser);
// Pass analyser to control panel via IPC

Fix 3 — Loudness normalization in ffmpeg.js

Add two passes to ffmpeg.js. The dual_mono=true flag is mandatory — omitting it causes a 3dB level error on mono microphone sources in stereo tracks.

// ffmpeg.js — loudnorm pass (add to audio filter chain)
const audioFilters = [
  'arnndn=m=sh.rnnn',          // RNN denoiser (bundled model)
  'acompressor=threshold=-18dB:ratio=4:attack=5:release=50',
  'loudnorm=I=-16:TP=-1.5:LRA=11:dual_mono=true',
  'alimiter=level_in=1:level_out=1:limit=0.95:attack=5:release=50',
].join(',');

Fix 4 — Bluetooth headset warning

When a BT device enters HFP/SCO mode (mic active), sample rate drops to 8 kHz (CVSD) or 16 kHz (mSBC). Detect this via MediaTrackSettings.sampleRate after track opens and warn the user before they start recording.

const settings = micTrack.getSettings();
if (settings.sampleRate && settings.sampleRate < 44100) {
  warnings.push(`Bluetooth mic is in call mode (${settings.sampleRate/1000}kHz). Audio quality will be low. Consider switching to wired.`);
}
07 — Technical Spec · Library

Video Vault

A new BrowserWindow, opened from the control panel "My Recordings" button. Shows every MP4 and WebM in the configured save folder. Persistent index in vault.json next to the save folder.

Layout

  • Grid view: 3-column responsive grid. Card = thumbnail + filename + duration + date chip.
  • Hover-to-loop: On mouseenter, extract 2 seconds around the 10% mark (action is usually there) using <video> with currentTime scrubbing. Play muted loop on hover.
  • Click: Open in system player (shell.openPath).
  • Quick actions: Rename, Edit (opens Editor window), Copy path, Share, Delete.
  • Metadata row: Duration · Codec · Resolution · File size · Recorded date.

Edit suite

FFmpeg showwavespic filter generates a waveform PNG once. Displayed in a Canvas. Trim handles are absolutely positioned div elements with drag handlers. Scrubber is a hidden <video> element synced to handle position.

Trim pipeline

// In ffmpeg.js — trim (stream copy, near-instant)
async function trim(inputPath, outputPath, startSec, endSec) {
  return runFfmpeg([
    '-ss', startSec.toFixed(3),
    '-i', inputPath,
    '-to', (endSec - startSec).toFixed(3),
    '-c', 'copy',          // stream copy = no re-encode
    '-avoid_negative_ts', 'make_zero',
    outputPath
  ]);
}

Multi-cut / "Scratch That" pipeline

// Build a concat filter from an array of [start, end] keep segments
function buildConcat(segments) {
  const parts = segments.map((seg, i) =>
    `-ss ${seg[0]} -to ${seg[1]} -i ${INPUT} -map ${i}:v -map ${i}:a`
  );
  return [...parts, `-filter_complex concat=n=${segments.length}:v=1:a=1`];
}
09 — Technical Spec · AI

AI pipeline

Silence / pause detection

FFmpeg silencedetect filter parses audio for gaps above a threshold. Output is stderr text that maps to timestamps. No ML required for this step.

// ai-edit.js
async function detectSilences(videoPath, { noise='-50dB', duration=0.5 } = {}) {
  const stderr = await runFfmpegCapture([
    '-i', videoPath,
    '-af', `silencedetect=noise=${noise}:duration=${duration}`,
    '-f', 'null', '-'
  ]);
  // parse: "silence_start: 12.34\n silence_end: 13.78 | silence_duration: 1.44"
  const starts = [...stderr.matchAll(/silence_start: (\d+\.?\d*)/g)].map(m => +m[1]);
  const ends   = [...stderr.matchAll(/silence_end: (\d+\.?\d*)/g)].map(m => +m[1]);
  return starts.map((s,i) => ({ start: s, end: ends[i] }));
}

Whisper.cpp transcript sidecar

Whisper runs as a child_process from whisper-node npm package (bundles a prebuilt binary). Takes audio extracted from the recording. Returns word-level JSON timestamps.

// ai-edit.js — transcript
const { whisper } = require('whisper-node');

async function transcribe(videoPath) {
  // 1. Extract mono 16kHz WAV (Whisper's native format)
  const wavPath = videoPath.replace(/\.\w+$/, '.wav');
  await runFfmpeg(['-i', videoPath, '-ar', '16000', '-ac', '1', '-f', 'wav', wavPath]);

  // 2. Run Whisper (ggml-base.en model, ~150MB bundled)
  const result = await whisper(wavPath, {
    modelName:    'base.en',
    whisperOptions: { word_timestamps: true }
  });
  return result; // [{ start, end, text, words: [{word, start, end}] }]
}

Auto pause-trim using silence map

function buildKeepSegments(duration, silences, minGap=0.5) {
  const cuts = [];
  let cursor = 0;
  for (const s of silences) {
    if (s.end - s.start >= minGap) {
      cuts.push([cursor, s.start]);   // keep this segment
      cursor = s.end;
    }
  }
  cuts.push([cursor, duration]);
  return cuts.filter(([a,b]) => b - a > 0.1);
}
10 — Technical Spec · Grade

Color grade

.cube LUT format

Standard 3D LUT format. FFmpeg's lut3d filter accepts it natively. File is a 33×33×33 or 64×64×64 grid of RGB output values for every input RGB.

# ffmpeg.js — apply LUT
buildArgs({ lut: '/path/to/cinematic.cube' }) {
  // Add to video filter chain:
  'lut3d=/path/to/cinematic.cube:interp=trilinear'
}

Real-time LUT preview (compositor)

Upload the .cube data as a WebGL2 TEXTURE_3D in the recorder's canvas compositor. Apply as a fragment shader lookup on each composite frame before recording begins. This gives real-time graded preview in the bubble.

// WebGL2 fragment shader snippet
uniform sampler3D uLUT;
vec3 applyLUT(vec3 color) {
  vec3 scale = vec3((LUT_SIZE - 1.0) / LUT_SIZE);
  vec3 offset = vec3(0.5 / LUT_SIZE);
  return texture(uLUT, color * scale + offset).rgb;
}

Bundled LUT pack

Ship 6 cinematic LUTs with the installer (Creative Commons licensed): Warm Cinematic, Cool Desaturated, Film Fade, Punchy Contrast, Muted Earth, Monochrome. Each under 500KB as a 33³ .cube.

11 — Technical Spec · Codecs

Codec modernization

Hardware encoder selection

Probe at startup by attempting a 1-second test encode with each encoder. First one that succeeds becomes the default for the session.

// main.js — boot probe (runs once, ~200ms total)
const HW_ENCODERS = ['h264_qsv', 'h264_nvenc', 'h264_amf'];

async function probeHardwareEncoder() {
  for (const enc of HW_ENCODERS) {
    try {
      await runFfmpeg([
        '-f', 'lavfi', '-i', 'nullsrc=s=1280x720:r=30:d=1',
        '-c:v', enc, '-f', 'null', '-'
      ], { timeout: 3000 });
      return enc;
    } catch {}
  }
  return 'libx264';  // software fallback
}

AV1 road map

  • libsvtav1: Fastest AV1 encoder. ~30% smaller files than H.264 at same quality. Available in ffmpeg-static 6+. Use for export, not intermediate.
  • av1_nvenc: RTX 30+ series only. Checks same probe loop.
  • Intermediate: Keep H.264/VP9 as intermediate. AV1 for final export only — encoding latency too high for real-time composite.
  • WebCodecs: Available in Electron 33 (Chromium 130+). VideoEncoder API is stable. Can replace MediaRecorder for precise frame control. Deferred — requires a rewrite of recorder.js and is not needed for Build 9.

Recommended presets by quality tier

// ffmpeg.js — encoding presets
const PRESETS = {
  fast:    { preset: 'veryfast', crf: 25 },   // small files, quick
  balanced:{ preset: 'medium',   crf: 23 },   // default
  quality: { preset: 'slow',     crf: 18 },   // archive / master
};

Note: slow is only for archival export — 2× encode time for minimal visible gain on screen content. Never used as the recording intermediate.

13 — Architecture + Decisions

Four-mode architecture

The app works like Premiere: distinct workspaces for each phase of the production pipeline. One button switches mode. The AI layer runs underneath all four.

MODE 1
Camera
Device selection, countdown, record/pause/stop, live mic meter, camera bubble, region selector. Everything that happens before the recording exists.
AI: VAD indicator · retake marker hotkey
MODE 2
Edit
Waveform trim, in/out handles, multi-cut concat, silence removal slider, transcript view, filler word removal, stitch multiple clips.
AI: auto-silence trim · Whisper transcript · filler removal
MODE 3
Production
LUT browser + grade, background blur, noise reduction, loudness normalization, codec/resolution picker, hardware encoder probe.
AI: auto-loudnorm · suggested LUT by content type
MODE 4
Distribution
Video Vault library, R2 shareable link, YouTube direct upload, LinkedIn, TikTok Inbox, SRT export, transcript copy.

Resolved decisions

✅ Q1 — Cloud hosting → Cloudflare R2

Zero egress fees. Files stored at $0.015/GB. Upload via @aws-sdk/lib-storage (R2 is S3-compatible). Pre-signed URL copied to clipboard. Ships as the first Distribution feature — no OAuth, no platform review, one API call. Prerequisite for Instagram (which only accepts public HTTPS URLs, not binary uploads).

✅ Q2 — Whisper model → base.en (148MB bundled)

Recommended tier: 2–4× more accurate than tiny.en at screen-recording speech. Ships inside the .exe. Real-time factor ~0.1–0.3× (a 10-minute recording transcribes in 60–180 seconds on CPU). Enables word-level timestamps → filler removal → SRT export → transcript-based editing.

✅ Q3 — Social platforms → no paid APIs

Build order: R2 shareable link → YouTube → LinkedIn → TikTok Inbox mode → Facebook Pages. Twitter/X deferred (requires $100/month API access; surface only after owner decides to absorb the cost). Instagram deferred (90-second cap kills most screen recordings; personal accounts have zero API access).

✅ Q4 — Pause threshold → user-configurable slider, three presets

UI ships a labeled slider with three named stops so the owner can feel the difference on real recordings before committing to a default.

300ms — tight edit, broadcast pace 500ms — Loom default, natural speech 750ms — relaxed, keeps breathing room

Default on first open: 500ms. Persisted per user. The slider live-previews which pauses would be cut before applying.

✅ Q5 — Save folder → %USERPROFILE%\Videos\MOB Recordings

Created on first save if it does not exist. User can change it in settings. Vault index (vault.json) lives in the same folder.

✅ Q6 — Vault hover-loop → native <video> scrub

Set video.currentTime to 10% mark on mouseenter, play for 3 seconds, reset on mouseleave. Zero extra file, no GIF. CPU cost: negligible (H.264 decode on hardware).

MOB's recording-quality advantages over Descript

  • Hardware compositor. MediaStreamTrackProcessor at 11ms mean / 22ms p95. Descript captures via system screen recorder — no camera shape compositing, no hardware encoder probe.
  • 7 camera shapes + drag/resize. Descript has a fixed circular overlay. We ship rectangle, circle, pill, diamond, hexagon, triangle, full-frame.

Architecture: hidden BrowserWindow renderer

getUserMedia works naturally in Chromium. Silero VAD, Porcupine, and Vosk all run as Web Workers in a hidden BrowserWindow renderer — no PortAudio, no native module rebuild on each Electron version bump. The renderer posts detected commands to the main process via IPC; the main process dispatches to the appropriate pipeline handler.

// Electron main process — voice IPC bridge
const voiceWin = new BrowserWindow({ show: false, webPreferences: { nodeIntegration: true } });
voiceWin.loadFile('voice-engine.html');

ipcMain.on('voice:command', (_, { state, command }) => {
  CommandDispatcher.dispatch(state, command);  // routes to FFmpeg / recorder / vault
});

// voice-engine.html renderer
// Porcupine Web Worker → detects "Hey MOB" wake word
// Vosk Web Worker (grammar mode) → recognizes command phrase within 3s window
// AudioWorklet → captures mic PCM and feeds both workers
// On match: ipcRenderer.send('voice:command', { state, command })

State machine

Grammar re-initializes on state transition (~40ms). "Stop" only in grammar during RECORDING. Each LISTENING_* sub-state times out after 3 seconds if no command matches.

LISTENING_RECORDING7 phrases"done" / "stop recording" → EDITING · "pause" ⇄ "resume" · "cut that" / "new take" / "chapter here" / "highlight this"
LISTENING_EDITING12 phrases"remove filler words" / "trim silences" / "clean audio" / "add captions" / "make a clip" / "ready to grade" → GRADING
LISTENING_GRADING6 phrases"apply cinematic grade" / "apply clean grade" / "normalize audio" / "export for youtube" → DISTRIBUTING
LISTENING_DISTRIBUTING4 phrases"upload to youtube" / "copy share link" / "upload to tiktok" / "done"

Voice feedback rules

  • No audio during RECORDING. Any chime is captured by the mic and enters the final file. RECORDING state: visual-only feedback (floating toast, bottom-right, 1.2s fade).
  • All other states: four pre-recorded audio clips, embedded as base64 data URIs (no disk-read latency): wake, confirm, working, done/fail.
  • Toast content: command text + current state + action triggered. Disappears 1.2s after appear.
