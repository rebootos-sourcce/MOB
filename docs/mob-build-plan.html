MOB Decisions Schema Algorithms Sprints Cloudflare
Architecture Decision Records
Five Decisions That Fix Everything

Each ADR closes a category of bugs identified in the gap review. All are decided; none require further debate.

ADR-001 Local-First: SQLite in Electron is the Source of Truth DECIDED
Context
The original architecture described intelligence algorithms running in Cloudflare Workers and D1 as the primary store. This directly contradicts the "fully offline" product promise, requires internet for every operation, and means multi-GB video uploads must route through a Worker (blocked by the 100MB body limit).
Decision
SQLite in the Electron main process is the sole source of truth. All six intelligence algorithms run locally in Node.js. D1, R2, and Queues are a sync and distribution layer only — optional, never blocking the core loop. A recording can reach production without any Cloudflare account.
Consequences
Workers become thin API shims: auth, pre-signed URL generation, D1 replication writes, and Queue submissions. No algorithm logic crosses the network. R2 upload bypasses the Worker entirely via pre-signed URL. User data is never at risk if Cloudflare is down or the user is offline.
ADR-002 EDL (Edit Decision List) as a First-Class Schema Concept DECIDED
Context
When a user cuts a filler segment in Edit mode, the original recording timestamps survive but the exported clip has different timestamps. All downstream tables — captions, segments, chapters — reference the original recording timeline. After a cut, caption start_ms=12400 may now be caption start_ms=10900 in the export, breaking SRT files and YouTube chapter markers silently.
Decision
Add an edl_entries table recording which source ranges were kept and their remapped output positions. Provide a remapTimestamp(edlEntries, sourceMs) → outputMs function used by every table that generates export artifacts (captions, chapters, thumbnails).
Consequences
SRT export, chapter JSON, and thumbnail selection all call remapTimestamp before writing positions. Cuts stack correctly: a second cut is applied to already-remapped output positions. The original words and segments rows are immutable; EDL entries describe the edit without destroying source data.
ADR-003 Device Identity + Ownership Column on All Root Tables DECIDED
Context
No table has a user_id or device_id. When D1 is the sync target, any Worker request can read or overwrite any row. When multiple installations sync to the same D1 database, rows from different machines collide. The Worker has no way to scope queries or enforce ownership.
Decision
Generate a stable device_id (UUID v4) on first launch, stored in Electron's userData. Add device_id TEXT NOT NULL to recordings, distributions, and production_packages. Worker auth middleware validates a JWT whose sub claim equals the device_id. All D1 reads and writes are scoped to WHERE device_id = ?.
Consequences
Multi-device use requires explicit sharing flow (out of scope for V1). Single-device use is fully isolated. Worker never touches another device's rows. Local SQLite does not enforce this (only one device writes to it), but the column is present for schema parity with D1.
ADR-004 Cloudflare Queues + Durable Objects Replace KV for Distribution Jobs DECIDED
Context
The original design used KV as an async job queue (KV.put(jobId, status)). KV has no queue semantics: no FIFO ordering, no retry, no dead-letter handling, no exactly-once delivery. A Worker reading from KV to process jobs is a polling anti-pattern. KV TTL-based cleanup is a source of silent data loss.
Decision
Use Cloudflare Queues for async distribution jobs (YouTube upload, TikTok submit, etc.). Use a Durable Object (DistributionCoordinator) to track per-distribution state machine: pending → uploading → processing → published. Add resume_session_uri TEXT to the distributions table so interrupted uploads resume rather than restart.
Consequences
Queue consumer handles retries with exponential backoff automatically. The Durable Object holds the upload cursor so a 2GB video resumes from byte N, not byte 0. The distributions table becomes a read-only audit log of what the Durable Object decided.
ADR-005 Algorithm Correctness: Five Rules That Fix All Six Bugs DECIDED
Rules
R1 — Filler pre-pad goes BEFORE the word (speaker hesitates before saying "um"), post-pad is ≤50ms
R2 — start_ms is always max(0, computed_value) — never negative
R3 — Overlapping filler/silence segments merge by extending the last segment's end_ms
R4 — Caption overflow creates a new caption; it never merges with the next segment
R5 — Hashtag extraction uses TF-IDF; raw TF is insufficient for multi-recording corpora
Context
These five rules address: negative timestamps when the first word is a filler, phantom gaps from bidirectional padding, duplicate captions from overflow merging into adjacent segments, and useless hashtags on short single recordings where every term has TF=1.

EDL Remap Function (TypeScript)

/** Remap a source recording timestamp to its export position after cuts. */
function remapTimestamp(edl: EdlEntry[], sourceMs: number): number | null {
  for (const entry of edl) {
    if (sourceMs >= entry.source_start_ms && sourceMs <= entry.source_end_ms) {
      const offset = sourceMs - entry.source_start_ms;
      return entry.output_start_ms + offset;
    }
  }
  return null; // sourceMs was cut out — caller decides how to handle
}

/** Rebuild EDL output positions after a new cut is applied. */
function applycut(edl: EdlEntry[], cutStart: number, cutEnd: number): EdlEntry[] {
  const result: EdlEntry[] = [];
  let outputCursor = 0;

  for (const entry of edl) {
    // Ranges that don't intersect the cut pass through
    if (entry.source_end_ms <= cutStart || entry.source_start_ms >= cutEnd) {
      const duration = entry.source_end_ms - entry.source_start_ms;
      result.push({ ...entry, output_start_ms: outputCursor, output_end_ms: outputCursor + duration });
      outputCursor += duration;
    } else {
      // Split: keep the part before the cut
      if (entry.source_start_ms < cutStart) {
        const pre = cutStart - entry.source_start_ms;
        result.push({ ...entry, source_end_ms: cutStart, output_start_ms: outputCursor, output_end_ms: outputCursor + pre });
        outputCursor += pre;
      }
      // Keep the part after the cut
      if (entry.source_end_ms > cutEnd) {
        const post = entry.source_end_ms - cutEnd;
        result.push({ ...entry, source_start_ms: cutEnd, output_start_ms: outputCursor, output_end_ms: outputCursor + post });
        outputCursor += post;
      }
    }
  }
  return result;
}
Corrected Algorithm Specifications
Six Algorithms, All Bugs Addressed

Pseudocode is the spec. Implementation lives in main/intelligence/.

1 — Filler Detection 4 bugs fixed
Bugs Fixed
B1 Pre-pad was applied after the word — speaker hesitates BEFORE saying "um", not after
B2 No guard against negative start_ms on first-word fillers
B3 No overlap merge — sequential fillers produced a gap between adjacent padded regions
B4 Multi-word context phrases ("you know") can't be detected word-by-word without bigram pass
const FILLERS = new Set(['um','uh','hmm','uhh','umm','uh-huh','mhm']);
const PRE_PAD  = 150;   // ms before filler (ADR-005 R1)
const POST_PAD = 50;    // ms after filler

function detectFillers(words: Word[]): Segment[] {
  const segs: Segment[] = [];

  words.forEach(w => {
    const tok = w.word.toLowerCase().replace(/[.,?!;:]+$/, '');
    if (!FILLERS.has(tok)) return;

    w.is_filler = 1;
    const s = Math.max(0, w.start_ms - PRE_PAD);  // ADR-005 R1, R2
    const e = w.end_ms + POST_PAD;

    const last = segs.at(-1);
    if (last && s <= last.end_ms) {
      last.end_ms = Math.max(last.end_ms, e);          // merge (ADR-005 R3)
    } else {
      segs.push({ type: 'filler', start_ms: s, end_ms: e, text: tok });
    }
  });

  // Bigram pass for context phrases ("you know", "i mean")
  const BIGRAM_FILLERS = new Set(['you know','i mean','you see','right so']);
  for (let i = 0; i < words.length - 1; i++) {
    const bigram = words[i].word.toLowerCase() + ' ' + words[i+1].word.toLowerCase();
    if (BIGRAM_FILLERS.has(bigram)) {
      words[i].is_filler = words[i+1].is_filler = 1;
      const s = Math.max(0, words[i].start_ms - PRE_PAD);
      const e = words[i+1].end_ms + POST_PAD;
      const last = segs.at(-1);
      if (last && s <= last.end_ms) last.end_ms = Math.max(last.end_ms, e);
      else segs.push({ type: 'filler', start_ms: s, end_ms: e, text: bigram });
    }
  }
  return segs.sort((a,b) => a.start_ms - b.start_ms);
}
2 — Silence Detection 1 bug fixed
B1 No gap-merge parameter — adjacent silences with a brief word bridge were left separate, producing stutter cuts in the edit view
const SILENCE_MIN_MS  = 500;   // configurable — shorter gaps ignored
const GAP_MERGE_MS    = 200;   // merge silences separated by ≤ this

function detectSilences(words: Word[], minMs = SILENCE_MIN_MS): Segment[] {
  const raw: Segment[] = [];
  for (let i = 1; i < words.length; i++) {
    const gap = words[i].start_ms - words[i-1].end_ms;
    if (gap >= minMs)
      raw.push({ type: 'silence', start_ms: words[i-1].end_ms, end_ms: words[i].start_ms, text: '' });
  }
  // merge adjacent silences (ADR-005 R3)
  return raw.reduce((acc, s) => {
    const last = acc.at(-1);
    if (last && s.start_ms - last.end_ms <= GAP_MERGE_MS)
      last.end_ms = s.end_ms;
    else acc.push({ ...s });
    return acc;
  }, [] as Segment[]);
}
3 — Caption Formation 2 bugs fixed
B1 Overflow merged into the following segment, producing captions that start mid-sentence
B2 No gap enforcement between adjacent captions — SRT readers reject captions with identical or reversed timestamps
const MAX_LINE   = 42;   -- chars per line (EBU-TT recommendation)
const MAX_LINES  = 2;
const MIN_GAP_MS = 83;   -- 2 frames @ 24fps

function formCaptions(words: Word[]): Caption[] {
  const caps: Caption[] = [];
  let batch: Word[] = [], line = '', lines = 1;

  const flush = () => {
    if (!batch.length) return;
    caps.push({ seq: caps.length+1, start_ms: batch[0].start_ms,
                end_ms: batch.at(-1)!.end_ms,
                text: batch.map(w => w.word).join(' '), format: 'srt' });
    batch = []; line = ''; lines = 1;
  };

  for (const w of words) {
    const test = line ? line + ' ' + w.word : w.word;
    if (test.length > MAX_LINE) {
      if (lines < MAX_LINES) { lines++; line = w.word; batch.push(w); }
      else { flush(); line = w.word; batch = [w]; }   -- ADR-005 R4: overflow = new caption
    } else { line = test; batch.push(w); }
  }
  flush();

  -- Enforce inter-caption gap (ADR-005 — no overlap)
  for (let i = 1; i < caps.length; i++) {
    if (caps[i].start_ms - caps[i-1].end_ms < MIN_GAP_MS)
      caps[i-1].end_ms = caps[i].start_ms - MIN_GAP_MS;
  }
  return caps;
}
4 — Hashtag Extraction (TF-IDF) 1 bug fixed
B1 Pure TF means every unique word scores identically on a single recording — IDF component needed to surface distinguishing terms across the corpus
const STOPS = new Set(['the','a','an','is','it','i','you','we','my',
  'and','or','but','so','to','of','in','on','at','be','are','was','this']);
const PLATFORM_CAPS = { youtube: 15, tiktok: 5, linkedin: 10, twitter: 3 };

function extractHashtags(
  transcript: Transcript, corpus: Transcript[], platform: string
): string[] {
  const tokens = transcript.full_text!
    .toLowerCase().split(/\W+/)
    .filter(t => t.length > 3 && !STOPS.has(t));

  // TF
  const tf: Record = {};
  tokens.forEach(t => tf[t] = (tf[t] ?? 0) + 1);

  // IDF — log(N / (1 + docs containing term))
  const N = corpus.length || 1;
  const scores: Record = {};
  for (const [term, freq] of Object.entries(tf)) {
    const df = corpus.filter(doc => doc.full_text?.includes(term)).length;
    const idf = Math.log(N / (1 + df));
    scores[term] = (freq / tokens.length) * idf;
    // save to metadata_tags.idf_score for caching
  }

  // Compound tags via bigram
  const bigrams: Record = {};
  for (let i = 0; i < tokens.length - 1; i++) {
    const b = tokens[i] + tokens[i+1];
    bigrams[b] = (bigrams[b] ?? 0) + 1;
  }

  const top = Object.entries(scores).sort((a,b) => b[1]-a[1]).slice(0,12).map(([t]) => t);
  const topBi = Object.entries(bigrams).filter(([,c]) => c > 1)
                      .sort((a,b) => b[1]-a[1]).slice(0,5).map(([b]) => b);

  const cap = PLATFORM_CAPS[platform] ?? 10;
  return [...new Set([...top, ...topBi])].slice(0, cap).map(t => '#' + t.replace(/\s+/g,''));
}
5 — Energy Scoring new spec

Assigns a 0.0–1.0 energy value to each segment using RMS amplitude from the decoded audio buffer. High-energy segments surface in the Edit mode as highlight candidates.

/** audioFloat32: PCM samples from Web Audio decodeAudioData, range -1.0 to 1.0 */
function scoreSegmentEnergy(
  audioFloat32: Float32Array, sampleRate: number,
  segment: Segment
): number {
  const start = Math.floor((segment.start_ms / 1000) * sampleRate);
  const end   = Math.min(audioFloat32.length, Math.floor((segment.end_ms / 1000) * sampleRate));
  if (end <= start) return 0;

  let sum = 0;
  for (let i = start; i < end; i++) sum += audioFloat32[i] * audioFloat32[i];
  const rms = Math.sqrt(sum / (end - start));

  // Normalize: typical speech RMS ≈ 0.02–0.25 on normalized float
  return Math.min(1.0, rms / 0.25);
}
6 — Production Package Assembly 1 fix (title API)
B1 Title generation made a Claude API call that is dead code — no API key is bundled. Title comes from the highest-energy segment's text, cleaned up locally.
function assemblePackage(recording: Recording, transcript: Transcript,
  segments: Segment[], captions: Caption[], hashtags: string[]): ProductionPackage {

  // Title: take text of the highest-energy non-filler segment, 60 char max
  const best = segments
    .filter(s => s.type === 'speech' && s.energy > 0.5)
    .sort((a,b) => b.energy - a.energy)[0];
  const title = best ? best.text.substring(0, 60).trim() : (recording.title ?? 'Untitled');

  // Chapters: segments with energy > 0.6 and duration > 15s become chapter markers
  const chapters = segments
    .filter(s => s.type === 'speech' && s.energy > 0.6
              && (s.end_ms - s.start_ms) > 15000)
    .map(s => ({ ms: s.start_ms, label: s.text.substring(0, 40) }));

  return {
    id: `pkg-${Date.now().toString(36)}-${crypto.randomUUID().slice(0,6)}`,
    device_id: recording.device_id,
    recording_id: recording.id,
    title,
    description: transcript.full_text?.substring(0, 500) ?? '',
    hashtags_json: JSON.stringify(hashtags),
    chapters_json: JSON.stringify(chapters),
    generated_by: 'whisper',
    created_at: new Date().toISOString(),
  };
}

Worker Auth Middleware

// workers/src/auth.ts
import { SignJWT, jwtVerify } from 'jose';

export async function authMiddleware(req: Request, env: Env): Promise<string | Response> {
  const header = req.headers.get('Authorization') ?? '';
  if (!header.startsWith('Bearer ')) return new Response('Unauthorized', { status: 401 });
  try {
    const { payload } = await jwtVerify(
      header.slice(7),
      new TextEncoder().encode(env.JWT_SECRET)
    );
    return payload.sub as string;  // device_id
  } catch { return new Response('Forbidden', { status: 403 }); }
}

Pre-Signed R2 Upload Route

// POST /api/presigned  — returns a URL the client uploads directly to R2
export async function handlePresigned(req: Request, env: Env): Promise<Response> {
  const deviceId = await authMiddleware(req, env);
  if (deviceId instanceof Response) return deviceId;

  const { recording_id, content_type, size_bytes } = await req.json() as any;
  const key = `recordings/${deviceId}/${recording_id}.mp4`;

  const presignedUrl = await env.R2_BUCKET.createMultipartUpload(key);
  // Return the R2 key (stored in recordings.r2_key) + upload URL
  return Response.json({ r2_key: key, upload_url: presignedUrl.uploadId });
}

Queue Consumer + Durable Object

// workers/src/queue-consumer.ts
export default {
  async queue(batch: MessageBatch<DistributionJob>, env: Env) {
    for (const msg of batch.messages) {
      const { distribution_id, device_id, platform } = msg.body;

      const id = env.COORDINATOR.idFromName(distribution_id);
      const stub = env.COORDINATOR.get(id);

      const result = await stub.fetch('http://do/process', {
        method: 'POST',
        body: JSON.stringify(msg.body),
      });

      if (!result.ok) {
        msg.retry({ delaySeconds: 60 });  // exponential backoff via Queue
      } else {
        msg.ack();
      }
    }
  }
};

// workers/src/durable/coordinator.ts
export class DistributionCoordinator implements DurableObject {
  state: { status: string; cursor: number; resume_uri?: string } = { status: 'pending', cursor: 0 };

  async fetch(req: Request) {
    const job = await req.json() as DistributionJob;

    if (this.state.status === 'published') {
      return Response.json({ ok: true, idempotent: true });  // no duplicate upload
    }

    this.state.status = 'uploading';

    // Resumable upload: use existing resume_uri if present
    const uploadUri = this.state.resume_uri
      ?? await initiatePlatformUpload(job.platform, job.r2_key);
    this.state.resume_uri = uploadUri;

    const { bytes_uploaded } = await resumeUpload(uploadUri, job.r2_key, this.state.cursor);
    this.state.cursor = bytes_uploaded;

    if (bytes_uploaded >= job.size_bytes) {
      this.state.status = 'published';
    }

    return Response.json({ ok: true, cursor: this.state.cursor, status: this.state.status });
  }
}
