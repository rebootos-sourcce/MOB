# Audit of the live build, 15 October 2026, five passes

The owner asked for "an audit of the atuned.world site five times" to find
every remaining P0 gap and every KPI gap. This sandbox cannot reach
atuned.world or the live Worker (every request times out), so the five
passes ran against the exact commit the live site serves: MOB main
`ed5eca3`, published by deploy run 38169307942 on 11 October, whose last step,
"Cloudflare serves this commit in production", passed. The build was made
fresh from that commit the way the deploy job makes it. Counts below are
read off the runs of 15 October, never typed from memory.

Two facts frame everything:

- **CI cannot run on either repository.** Every GitHub Actions run since 15
  October 19:14 UTC fails in two seconds with "The job was not started
  because an Actions budget is preventing further use." Local runs are the
  only evidence until the owner raises the spending limit.
- **Two repositories publish two different applications to the same
  Cloudflare Pages project, `atuned`, which is atuned.world.** The last push
  wins. Details in `ORIENTATION.md` section 1.

## The KPI gaps

The product has no KPI definition in MOB at all. Reboot-OS's bible sets
return targets (day 1 35 percent, day 7 22, day 30 12) and its checklist
rules analytics out as a privacy promise. The marketing seat's ladder
resolves that, and it is the team's position until the owner rules
otherwise:

| KPI | Counted as | Countable today |
|---|---|---|
| Landing to quiz | quiz loads over landing loads | Only from Cloudflare's own totals, which the privacy page already names |
| Quiz to app | sessions opened from a quiz link over quiz loads | No. The session does not record which door opened it. One new field |
| Ground chosen | sessions with a ground over sessions opened | Yes, on the server |
| Tutorial done | over ground chosen | Yes |
| First release, then the check | over tutorial done | Yes, from 14 October (migration 0015) |
| Joined to an account | over sessions opened | Yes |
| First paid month | first paid invoices over accounts | Ready, reads zero: Stripe not set up, checkout closed |
| First cancel | subscriptions ended over paid | Ready, reads zero |
| Day 1, 7, 30 return | accounts back on day N over accounts made | No, and must not be: "nothing about how you use the app is reported to us". The alpha retention number is the second month's renewal, which Stripe sends |

The gaps, in order: the privacy paragraph (above); one read only totals
query over the funnel sessions, run by hand weekly, no dashboard, no new
event (half a day); the quiz door field (one field, after the privacy
paragraph); Stripe live so the paid and cancel rows stop reading zero.
Nothing else is a KPI gap. An "app opened" event is not a gap, it is a
promise broken, and no seat will build it.
