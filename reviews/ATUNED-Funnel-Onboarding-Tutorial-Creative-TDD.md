# 1. PURPOSE

This document defines the complete creative and narrative experience from the public ATUNED funnel through onboarding and the first meaningful product experience.

It is written as a handoff to a production team that did not participate in the previous design conversations.

The objective is not simply to specify screens or copy.

The objective is to specify the **experience the user should have**.

ATUNED should feel like a living instrument that gradually reveals something about the user through their own experience.

The user should not feel:

> I am completing a funnel.

They should feel:

> Something is happening in me.  
> I can feel it.  
> I can see it.  
> ATUNED is helping me understand it.  
> I can test whether what it sees is right.  
> I can work with it.  
> I can see what changes.  
> I can come back when something else happens.

The experience therefore needs to be:

**welcoming, slow enough to breathe, visually coherent, emotionally intelligent, transparent, curious, self-explanatory, and progressively more useful.**

It must never feel rushed.

It must never make the user feel behind.

It must not force the user to understand the entire ATUNED model before experiencing it.

The product should demonstrate the mechanics before explaining all of them.

# 2. EXISTING PRODUCT SPINE

The creative system must preserve the current ATUNED architecture rather than creating a parallel conceptual system.

The current product is organized around:

**DISCOVER → PLAY → FLOW → EMBODY → DISCOVER**

The intended meaning is:

### DISCOVER
Tell ATUNED what is happening.

### PLAY
Interact with what ATUNED noticed.

### FLOW
Work with the confirmed pattern and release it.

### EMBODY
Notice what changes and bring the work into lived experience.

Then life continues.

The next thing that happens becomes the next Discover event.

The loop is therefore not a four-step workflow that ends.

It is a continuous cycle.

# 4. CREATIVE NORTH STAR

The central creative idea is:

> **See what is running you.**

The deeper promise is:

> **See where you are.  
> See what is holding you there.  
> Take one thing off.  
> See what changed.**

The experience should not promise to fix a person.

It should not tell a person who they are.

It should show them what ATUNED notices, let them test it, let them correct it, and give them something concrete to work with.

The user's own experience remains primary evidence.

# 5. AUDIENCE EXPERIENCE

The first-time user is assumed to have some combination of:

- a felt problem;
- a recurring situation;
- emotional or mental strain;
- body sensations;
- curiosity;
- skepticism;
- fatigue with generic self-help;
- uncertainty about what is actually happening;
- a desire to understand themselves without being judged.

The product must accommodate all of those states.

The user may arrive thinking:

> I am anxious.

Or:

> I keep getting angry.

Or:

> Something feels wrong.

Or:

> I know what I should do and I still don't do it.

Or:

> I am exhausted.

Or:

> I don't know what is wrong.

ATUNED does not require the user to already know the pattern.

That is one of the reasons the signal test and story experience exist.

# 6. THE MOST IMPORTANT PACING RULE

## Never make the user feel behind.

There is no countdown.

There is no urgency language.

There is no artificial scarcity during the experiential journey.

There is no:

> 63% complete.

There is no:

> Don't leave now.

There is no:

> You have 37 questions left.

There is no requirement to understand every concept before proceeding.

The user can pause.

The user can return.

The user can sit with a result.

The user can choose to continue.

The experience should feel like:

> **You have time. Notice what is here.**

This is a core emotional feature, not merely a usability feature.

# 53. FAQ COPY

## What is ATUNED actually doing?

> ATUNED listens to the way you describe what is happening in your life. It looks for patterns in your words and experience, shows you what it notices, and lets you decide whether it got it right. From there, you can work with the pattern and observe what changes.

## How does ATUNED know where a pattern sits in my body?

> ATUNED uses a model of body addresses and somatic associations. Your words and reported experience help select where the system looks. These addresses are part of the ATUNED model. They are not a medical diagnosis.

## How do I know the reading is accurate?

> You don't have to take it on faith. ATUNED shows you what it heard and what it thinks may be happening. You can confirm it, reject it, or correct it.

## What happens if ATUNED gets me wrong?

> Say so. “Not me” stops that interpretation from becoming confirmed knowledge. You can tell ATUNED what feels closer, and it can work from the correction.

## What's the difference between release and reframe?

> Release interrupts the old pattern. Reframe gives the story a new direction. Release creates space. Reframe gives you something new to work with.

## What should I expect to feel?

> Anything from a clear shift to almost nothing. You don't have to force a sensation. If your mind is very active, subtle changes can be difficult to notice. No sensation is also information.

## Why would I use ATUNED again?

> One pattern is rarely the whole story. You can return to the same ground, explore another pattern, see what changed, and continue building a record of what you're working with.

## Does ATUNED remember?

> The product is designed to remember confirmed patterns, corrections, releases, practices, evidence, and outcomes so each session can build on what came before.

## Is ATUNED therapy or a personality test?

> ATUNED is an instrument for self-observation and practice. It is not presented as a replacement for clinical care, diagnosis, or therapy.

## Is my information private?

> The exact privacy language must match the implemented storage, account, API, and server architecture. The public copy should make only claims that the production implementation can support.

# 59. COHERENCE MEASUREMENT CONTRACT

The CQ system should remain:

**0–100**

```text

40–60    OSCILLATING
```

These boundaries are a product rule proposed in this document and must be explicitly encoded as a versioned configuration rather than silently assumed by frontend code.

The system should store:

```text
cq_value
cq_ceiling
gap_value
direction_state
direction_rule_version
```

The baseline must be immutable.

A new measurement becomes a new observation.

# 60. GAP CONTRACT

At the top level:

```text
gap = cq_ceiling - cq_value
```

If:

```text
cq_ceiling = 100
cq_value = 62
```

then:

```text
gap = 38
```

The gap should not be treated as a personal deficiency score.

It represents the remaining difference from the modeled coherence ceiling.

The system should then associate contributing evidence and patterns with the gap without claiming that every contributing factor has a mathematically proven one-to-one causal relationship with the gap.

Correction changes the model.

ATUNED can suggest. The user decides.
