Atuned information system

One definition, one table, three ways in. Prototype, no network.

The rule

  1. A name is glossed once, in one table, and the tip shows it. Nothing else may carry a definition.
  2. A number says what it is out of, on the surface. Never in the tip.
  3. A control says what it does in its own label. A tip only when the label cannot.
  4. A reading explains itself in its drill. The tip is the door to it, not a second copy of it.
  5. A name with no gloss is a defect. The gate counts them and the count is read off the run.

Five lines, one per kind of question this product raises about itself. No diagram, because a system that needs one is not the system that was asked for.

    The gate, running on this page

    Every name on this page is checked against the table at load. A name with no entry is reported by name, which is the same shape validateProfile already uses at the boundary: refuse by name, never clamp. Read the count off the run.

    What is not here

    No second panel, no help mode, no tour, no onboarding overlay, no third depth. The tip is the short answer, the drill is the long one, and Nielsen Norman put the ceiling at two levels of disclosure. Everything on this page is one attribute and one lookup on top of the tooltip that is already designed.
